## Acceptance matrix additions / clarifications

### D-00 — Create initial workspace

**Test:** Starting without an existing JL Mixing workspace, create a new workspace using Studio.

**Expected result:** The user chooses a parent location with a native folder picker. Studio creates a new `Mixes` workspace there using Automation's existing `new-studio --root` semantics, validates it, makes it the configured workspace, and makes it available without Terminal, Finder, or a restart. Failed creation leaves the previous workspace configuration unchanged and surfaces actionable feedback.

**RC1 result:** **Fail** — #238.

**Fix status:** Implemented on the RC-fix branch; packaged retest required.

### D-01 — Configure/select workspace clarification

The workspace `Change` interaction uses a native directory/folder picker rather than requiring manual entry of an absolute path. The selected folder is still only a candidate: Studio validates it before `Use This Workspace` can save it. Cancel or failed validation leaves the configured workspace unchanged.

**RC1 result:** **Fail** — #233.

**Fix status:** Implemented on the RC-fix branch; packaged retest required on macOS and Windows.

### D-26 — Success feedback

Routine success feedback is transient and non-blocking, while warnings/errors remain actionable and persistent where required. Success notifications must be removed after their display interval rather than merely becoming visually transparent.

**RC1 result:** **Fail** — #234.

**Fix status:** Implemented with explicit auto-dismiss behavior; packaged retest required.

### D-28 — File-table modified-date consistency

**Test:** Compare Modified timestamps across Files, Client Files, Audio Prep, Revisions, Delivery, and other project file tables that expose the same field.

**Expected result:** File-table timestamps use the established Studio presentation format without the inconsistent date/time comma and with consistent am/pm treatment.

**RC1 result:** **Fail** — #236.

**Fix status:** Implemented in the shared project file service with regression coverage; packaged retest required.

### Settings > About — #237

The application version is now in release scope for Studio 2.0. Settings contains a low-noise **About** panel displaying:

- authoritative packaged JL Mixing Studio version;
- detected JL Mixing Automation version when available;
- Automation API version used by this Studio release.

This is a diagnostics/support surface and does not add version information to daily project chrome.

**Fix status:** Implemented; packaged retest required.

## Deferred enhancement

### Files screen navigation — #235

The question of removing the Files screen inner left-side navigator is explicitly deferred to a later release. The 2.0 RC keeps the current Files layout unchanged. #235 remains the future design/usability tracker and does not block Studio 2.0.

## RC1 disposition

RC1 retains its original failed results. The RC-fix branch addresses #233, #234, #236, #237, and #238; #235 is deferred. None of these implementation changes retroactively alter the RC1 acceptance result.

Before the next Studio candidate can be accepted, rerun D-00, D-01, D-26, D-28, Settings > About verification, and the affected packaged platform checks against a new immutable RC tag rather than modifying `v2.0.0-rc.1`.
