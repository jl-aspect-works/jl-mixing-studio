# Studio v2.2 performance review

## Scope

This pass reviews steady-state work introduced or affected by Listening Phase 1 before the first Studio 2.2 release candidate. It preserves the one-second Listening reconciliation cadence and shared-workspace correctness.

## Material finding and correction

### Active-project monitoring rebuilt the whole workspace every second

After #359, each monitor tick performed one `discover_workspace_at()` call. The duplicate Delivered Listening discovery and unchanged frontend notification churn were already removed, but the remaining discovery still:

- validated every client and project manifest;
- read every valid delivery manifest;
- sorted the complete workspace; and
- derived global Tasks and Activities.

The monitor only needs the selected project's current revision, delivery summary, and validated filesystem path. Repeating global derivation once per second is avoidable work, especially when the workspace is on a NAS or mounted synchronized folder.

The monitor now uses stable client/project IDs to perform active-project-scoped discovery. It still validates the Studio document, selected client, selected project/revision history, delivery cross-document identity, duplicate IDs, symlinks, and path containment. It no longer opens projects belonging to unrelated clients or derives global Tasks/Activities.

Deterministic operation-count change per active monitor tick:

| Work | Before | After |
| --- | --- | --- |
| Full workspace discovery | 1 | 0 |
| Global Tasks/Activities derivation | 1 | 0 |
| Active-project validated discovery | 0 | 1 |
| Revision reconciliation | 1 | 1 |
| Delivered reconciliation | 1 | 1 |

## Production timing evidence

Debug logging now records `listening_monitor_scan_completed` with:

- `configuration_duration_ms`;
- `project_discovery_duration_ms`;
- `revision_reconciliation_duration_ms`;
- `delivered_reconciliation_duration_ms`; and
- `total_duration_ms`.

If a completed scan takes at least the one-second polling interval, Studio emits `listening_monitor_scan_slow` at the normal info log level. Repeated slow scans remain quiet until `listening_monitor_scan_speed_recovered` records recovery; per-scan measurements remain available at debug level. Normal fast scans add no info-level log traffic. These fields separate workspace/path cost from destination audio/metadata/artwork cost when diagnosing a slow local or NAS installation.

## Other reviewed paths

### Workspace and navigation refresh

Workspace refreshes remain coalesced while one discovery is in flight. Opening a project and returning window focus refresh authoritative workspace state, but switching among tabs within the same project does not independently trigger the route-level full discovery. Background refresh does not invalidate the recursive storage summary.

### Workspace storage summary

Recursive storage scans remain asynchronous, coalesced, and limited to initial/explicit invalidation. Listening monitor events do not request a storage rescan.

### Project file access

Project file browsing continues to use stable-ID project resolution and a project-relative directory listing. It does not rebuild the complete workspace merely to list the active folder.

### Audio preview

The native audio status timer runs every 200 ms only while the player component has an active native preview session. It is not a workspace/filesystem scan and is stopped by component cleanup. No change is justified for 2.2.

### Destination freshness checks

Revision and Delivered Listening continue checking destination audio, metadata, and artwork at the one-second project-monitor boundary. This is intentional self-healing behavior. Slowing or sampling these checks without production evidence would increase repair latency and weaken the accepted contract. The new phase timings will identify if a specific destination makes this the dominant cost.

## Regression coverage

Tests verify that active-project discovery:

- returns the selected project and delivery without depending on unrelated invalid project siblings; and
- retains delivery-manifest identity/integrity rejection.

Existing monitor, deletion recovery, metadata/artwork freshness, refresh coalescing, and cross-platform Listening tests remain the behavioral safety net.

## Deferred changes

No filesystem-watcher redesign, persistent workspace index, virtualized table layer, or reduced self-healing cadence is justified before 2.2 RC. Those changes add invalidation complexity and should require production timing evidence showing that scoped discovery is insufficient.
